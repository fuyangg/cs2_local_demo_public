# 浏览器上传分析

## 使用

1. 运行应用，打开其页面。在左侧选择或拖入已解压的 CS2 `.dem`。
2. 点击“上传并分析”。页面显示检查与保存上传内容、解析比赛事件和回合的状态。
3. 分析完成后，按已有流程选择回合，点击“查看这 N 个回合”，播放、拖动时间轴或筛选玩家与道具。

页面不提供服务器目录浏览或本地路径输入。上传通过浏览器 HTTP 请求传到应用服务器；后续位置和道具解析直接使用服务器保存的副本，不需要访问客户端原文件。CLI 和独立本地开发 API 仍保留原有路径接口。

同一内容换名上传会复用现有解析缓存，页面显示本次用户提供的文件名。提交新分析失败时清除当前页面的旧比赛结果，避免将上一场结果误认为本次上传的结果；可以修复文件后再次上传。

## 存储与大小

上传副本位于当前环境的 `data/dev/uploads/<SHA-256>.dem`，prod 使用自己独立的 `data/prod/uploads/`。文件名只用于显示，不作为服务器路径，因此同名不同内容不会覆盖。现有 Parquet 缓存版本不变，上传副本、缓存和临时文件都不提交 Git。

先检查 `.dem` 扩展名和 CS2 `PBDEMS2` 文件头，再按 8 MiB 分块写临时文件并计算 SHA-256，通过后原子发布。文件检查或解析失败会清理此次新建的上传副本与临时文件，已存在的相同内容文件保留。上传文件在成功后继续保存，用于之后按需提取位置和道具；服务重启后可重新上传相同文件复用缓存。

默认单文件最大 2048 MiB，托管启动脚本、`.streamlit/config.toml` 和应用校验保持一致。Streamlit 会先在内存缓冲浏览器上传，应用分块落盘避免额外复制整份字节内容；这不表示零内存上传，也不是分片续传。托管平台、代理、内存或磁盘可能有更低限制，2 GiB 边界由合成测试验证，不承诺小内存机器能处理该大小。修改上限时需同时调整服务器和应用校验。

## 运行位置

公开 GitHub 仓库提供源代码，仍需要启动或部署应用。`bash scripts/run-dev.sh` 默认在本机 `127.0.0.1:8501` 运行；部署在远程机器时，上传和分析发生在远程机器。平台或反向代理需要支持 Streamlit 的 HTTP 上传和 WebSocket 连接，以及所需的文件大小、存储和分析资源。

当前改动提供上传入口，没有自动发布公网服务，也没有添加多用户账号、任务隔离或配额系统。服务器不向页面列出已保存的其他上传；页面仅使用当前会话明确提交的文件。开发 API 仍按原有规则仅供本机访问。
