# 人物编号与回合筛选

## 编号与线型

`player_color` 来自 Demo 中的玩家控制器属性。解析器可能返回颜色名称，平台统一为：

| 编号 | 名称 | 显示颜色 |
|---|---|---|
| 0 | yellow | 黄 |
| 1 | purple | 紫 |
| 2 | green | 绿 |
| 3 | blue | 蓝 |
| 4 | orange | 橙 |

原始颜色与统一编号保存在位置缓存中，浏览器按每条观测的编号着色。Steam ID 仍是身份主键；颜色编号在两队之间可能重复，不能代替玩家身份。无效或缺失编号使用灰色与 `?`，不按昵称、Steam ID 排序或当前队伍补造编号。

T（`team_num=2`）使用虚线，CT（`team_num=3`）使用实线；轨迹与标记轮廓均遵循这一规则。静态快照的轨迹同样按编号和阵营着色、设置线型。换边以每条状态的阵营为准。

## 队伍与阵营

打开比赛时，在各回合的冻结结束附近读取少量实际状态，记录阵容、队名、已完成回合数和加时字段，保存到本地 `round_context.parquet`。

队伍 A/B 为稳定别名：第一个可识别的非预热快照中，T 方阵容为 A，CT 方阵容为 B。之后通过 Steam ID 阵容的无歧义重叠匹配识别两队，换边不改变身份。能够取得 `team_clan_name` 时展示真实队名；缺失时保留“队伍 A/B”。该别名不宣称等于赛事官方的主客队编号。

每回合记录 `team_a_side` 和 `team_b_side`，所以“队伍 A + T”选择的是这支队伍进攻的回合，“队伍 A + CT”选择防守回合。两队阵容均无法可靠匹配时保持未知，不把当前 T 方直接当成永久的 A 队。

## 常规与加时

使用明确字段 `CCSGameRulesProxy.CCSGameRules.m_nOvertimePlaying`：大于 0 为加时，0 为非加时，缺失为未知。不会依据回合号超过 24/30 推断，以兼容 MR12、MR15、预热、刀局、重启和不完整录像。

“常规/加时”筛选均排除未知值；用户仍可在“全部阶段”中手动选择。显示的 R 编号是平台录制回合标识；另存 `official_round_number` 作人工核对，不强行将重启前后相同的比赛回合编号合并。

## 选择与容量

- 回合表可直接勾选，最多选择 20 个。
- 队伍、阵营、阶段、经济/配枪过滤按 AND 组合。
- “勾选筛选结果”替换当前选择；结果超过 20 个时禁用，并提供明确的“只选前 20 个”操作。
- 手动跨筛选条件勾选会保留之前的选择，已选计数包含当前过滤视图之外的回合。
- 默认自动精度对 1–8 个回合使用 16 Tick 间隔，9–20 个回合使用 32 Tick 间隔；高级设置可改精度。单个回合与播放器总行数仍有明确上限，超限会报错而非静默截断。

## 缓存升级

基础比赛数据继续使用既有数据集；新版位置缓存以 `positions-v3-r<id>-step<间隔>.parquet` 保存，含 `player_color` 与 `player_color_id`。旧位置文件保留，新版首次加载时按需重算，多个回合合并解析。队伍/加时读取失败不会覆盖基础数据，诊断记录于数据集目录。

## 地图与全屏

地图尺寸调整改变 Canvas 的显示高度和渲染分辨率，保持地图与玩家同一投影比例。浏览器原生全屏包含地图、时间轴和播放/玩家控件；Esc 或退出按钮返回。嵌入权限受限时，可选择独立窗口，回放数据以本地 Blob 传入，不经过远程上传，并保留时间点、回合和玩家选择。

已观测轨迹在浏览器中缓存为独立绘图层；跨采样、楼层、玩家/回合选择、地图平移/缩放和尺寸变化时更新，减少逐帧重复工作。插值只用于显示，原始位置不修改。


## 经济与配枪

“经济 / 配枪”依据观察队伍在冻结结束后 1 Tick 的完整五人快照分类，换边后仍按稳定队伍身份归属。回合表同时显示人均装备价值、人均本回合花费、AWP 数；分类按装备价值（含保下/已持有装备），不按现金余额或当局花费，不宣称能识别强起意图。

| 选择 | 判断规则 |
|---|---|
| 手枪局 | 明确的半场/比赛开始元数据，非预热、非加时，五人开局资金均不超过 $800，至少三人持有手枪；不依赖固定第 13/16 回合，也不把纯刀局当作手枪局 |
| eco | 全队人均装备价值低于 $2,000（手枪局优先） |
| force-buy | $2,000 ≤ 人均装备价值 < $4,000 |
| 4k-buy | $4,000 ≤ 人均装备价值 < $5,000 |
| full-buy | 人均装备价值 ≥ $5,000 |
| double-awp | 完整五人武器清单中至少两把 AWP，是独立配枪标签，可以与 full-buy 等装备档位重叠 |
| 经济未知 | 缺失冻结结束、队伍归属、完整五人快照或有效装备价值；武器清单不足时 AWP 数保持未知而非 0 |

经济筛选使用新版独立 `round-economy-v1.parquet`。重新打开比赛会为已有数据集补充缓存，不覆盖原 `round_context.parquet`、事件、位置或旧数据。部分信息无法解析时保留其他回放功能，诊断写入 `round-economy-v1-diagnostics.json`。未知信息不匹配已知经济档位，仍可切回全部经济手动选择。筛选与最多 20 回合的限制保持一致。
